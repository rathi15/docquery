## Decisions log (settled — do not re-litigate; rationale in Architecture.md)
- 2026-07-17 · Backend-only REST API. No frontend for the 3 weeks (parked).
- 2026-07-17 · OpenAI for embeddings (text-embedding-3-small, 1536 dims) and chat,
  via Spring AI. Provider change must be flagged BEFORE Phase 5 (affects vector dim).
- 2026-07-17 · Spring AI managed `vector_store` table with metadata filters — NOT a
  custom JPA chunk entity. Vector deletes centralized in DocumentService.
- 2026-07-17 · Upload returns 202; ingestion is @Async with bounded pool — no queue.
- 2026-07-17 · Citations built from retrieved chunks, never LLM-generated.
- 2026-07-17 · Flyway from day one; JPA/Postgres/Flyway deps enter only in Phase 2,
  Spring AI deps only in Phase 5 (build stays green daily).
- 2026-07-17 · Deploy = single EC2 free-tier box + Docker Compose, Postgres co-located
  (not RDS) — deliberate portfolio trade-off.
- 2026-07-17 · 404 (not 403) for other users' documents — no existence leak.
- 2026-07-17 · Docs live in `docs/` in the repo; Memory.md updated each session.
- 2026-07-17 · Pinned **Spring Boot 3.5.16** (final 3.x patch; the line reached OSS
  EOL 2026-06-30) over Boot 4.1.0, specifically to pair with **Spring AI 1.1.x GA**
  instead of the still-pre-GA Spring AI 2.0 (Boot-4-compatible line). Chosen
  deliberately over the newer Boot 4.1.0 the initializr had generated by default —
  stable/GA beats bleeding-edge for a 3-week deadline. Revisit only if Spring AI 2.0
  reaches GA before Phase 5 and there's a concrete reason to move.

- Bugs + lessons (keep — interview material):
  - Bug 1: "password authentication failed" — an old local Windows PostgreSQL was
    squatting on port 5432, answering before our container. Fix: moved our container to
    host port 5433. Lesson: auth-failed ≠ connection-refused; first ask "who is actually
    answering on this port?" (Get-Service *postgres*, netstat -ano | findstr :5432).
  - Bug 2: "relation users does not exist" — migration file was in the wrong folder, so
    Flyway silently found nothing and the app started anyway. Lesson: "app started" ≠
    "step worked" — always confirm the evidence line. Convention-based tools (Flyway's
    db/migration, GitHub's .github/workflows) never error on a wrong path, they ignore you.
