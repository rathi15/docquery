# DocQuery — Product Requirements Document

## One-liner
A backend-only REST API service where a user uploads documents (PDF/Word) and asks
questions in natural language, receiving answers grounded in cited passages from
their own documents (RAG — retrieval-augmented generation).

## Why this project exists (the real goal)
This is a portfolio project for Khushi Rathi (backend developer, 3+ yrs Java/Spring
Boot). Priorities, in order — every decision defers to these:
1. **Resume-ready in ~3 weeks**: deployed on AWS, tested, documented (README with
   architecture diagram and design decisions).
2. **Interview prep**: every design choice must be defensible. Always WHY, not just WHAT.
3. Possible future SaaS — but build ZERO features for hypothetical future users now.

## Target users
- **Primary (real)**: interviewers and recruiters evaluating backend + AI-integration
  skills. The "product" they consume is the repo, the live API, and the design story.
- **Hypothetical end user (drives requirements)**: a person with private documents
  (contracts, policies, notes) who wants trustworthy Q&A over them — answers with
  visible source passages, documents isolated per user account.

## Core features (in scope)
- **F1 — Auth**: register + login with email/password, JWT bearer tokens, all other
  endpoints protected.
- **F2 — Document management**: multipart upload (PDF/Word), list my documents with
  processing status, get one (incl. error message if failed), delete (must also
  remove its vectors).
- **F3 — Async ingestion pipeline**: on upload return 202 immediately; background:
  extract text (Tika) → chunk with overlap → embed → store in pgvector with metadata.
  Status lifecycle: UPLOADED → PROCESSING → READY | FAILED.
- **F4 — Q&A**: POST /query with a question (+ optional documentIds, topK);
  top-k similarity search filtered by userId; answer generated by chat model from
  retrieved chunks only; citations returned from the retrieved chunks themselves.
- **F5 — Operational quality**: Swagger/OpenAPI docs, /actuator/health,
  RFC 9457 ProblemDetail errors, Docker Compose, GitHub Actions CI, AWS deployment.

## Out of scope (parked — do not build, do not suggest)
Frontend UI of any kind · message queues · streaming responses · chat history /
conversation memory · file formats beyond PDF and Word · document sharing / teams ·
rate limiting · RDS / managed database · fine-tuning or custom models.

## Success criteria (definition of "done" for the 3 weeks)
- Live base URL on AWS free tier, demonstrable end-to-end via Swagger UI.
- Green CI badge on the README.
- JUnit unit tests for core logic + at least one Testcontainers integration test.
- README: what/why, architecture diagram, setup instructions, design-decisions section.
- Khushi can answer, unaided: why 202, why @Async not a queue, chunking strategy,
  how per-user isolation works, why citations come from retrieval, cost/scale story.
